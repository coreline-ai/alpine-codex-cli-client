# APK 내장 Python 런타임 구현 계획

- 작성 시각: 2026-08-15 14:19:17 KST
- 상태: 구현 완료 / 실제 production 패키지 입력 및 기기 E2E 대기
- 목표 배포물: 공개 `release` APK (페이지 6 제외)

## 개발 목적

Gateway 실행에 필요한 Python을 앱 실행 중 외부 저장소에서 내려받지 않고 APK 내부 패키지 팩만으로 설치한다. Codex/Grok OAuth 및 모델 통신을 제외한 외부 서비스·런타임 다운로드 의존성을 제거하면서 기존 로그인, 채팅, 로컬 Gateway, 2-slot 런타임 복구 동작의 회귀를 방지한다.

## 개발 범위

- Alpine `python3` 및 전이 의존 패키지의 APK 내장용 고정(lock) 포맷
- 빌드 시 로컬 패키지 팩의 파일명·크기·SHA-256·중복·누락 검증
- 앱 전용 경로에 패키지 팩을 원자적으로 스테이징하고 다시 검증하는 Android 코드
- `/sbin/apk add --no-network`와 절대 로컬 파일 목록만 사용하는 설치 경로
- 설치 전 simulate, 설치 후 Python/Gateway import smoke, 실패 시 미완료 상태 유지
- 공개 `release` 패키징의 실패-폐쇄(fail-closed) 정책 및 APK 산출물 검사
- 단위 테스트, Gradle 공급망 잠금, 배포/운영 문서 갱신

## 제외 범위

- 앱 실행 중 Alpine 저장소 또는 기타 외부 서비스에서 패키지 다운로드
- Codex/Grok OAuth 및 승인된 모델 통신 방식 변경
- 전체 Alpine rootfs 재제작 및 페이지 6 취약점 DB 완성
- 존재하지 않는 Python 패키지 바이트·해시·서명을 임의 생성
- 공개 배포 서명키 생성, 스토어 제출, 기기 재설치
- 기존 작업 트리의 무관한 변경 초기화·stash·삭제

## 공통 진행 규칙

- 실제 앱 실행 시 OAuth/모델 통신 외 네트워크 다운로드를 허용하지 않는다.
- 모든 설치 대상은 잠금 파일에 고정된 APK 내부 파일이어야 하며 패키지명만으로 해석하지 않는다.
- `--allow-untrusted`를 사용하지 않고 Alpine 패키지 서명 검증을 유지한다.
- 입력 패키지 팩이 없거나 불완전하면 공개 `release` 산출물을 만들지 않는다.
- 테스트용 합성 fixture와 실제 배포 패키지를 명확히 분리한다.
- 성공 검증 이전에 기존 런타임 slot을 완료 상태로 표시하지 않는다.
- 기존 수정사항을 보존하고 이 계획에서 변경한 파일만 추적한다.
