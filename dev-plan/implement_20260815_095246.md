# implement_20260815_095246.md

작성 일시: `2026-08-15 09:52:46 KST`

이 문서는 보안 전문가 검토에서 확인된 SEC-001~SEC-008을 기존 Codex/Grok 기능 회귀 없이 단계적으로 보완하고 공개 배포 산출물을 만들기 위한 실행 계획이다. 여기서 **회귀 0**은 변경 전 동작을 자동·실기기 인수 기준으로 고정한다는 의미다. 사용자 결정에 따라 Phase 6의 patched rootfs·Python 사전 번들·완전한 취약점 DB는 공개 배포 필수 조건에서 제외하며, 그 사유로 이후 Phase 진행을 차단하지 않는다.

## 개발 목적

- Gateway 탈취·위조, 동일 UID credential 접근, 구버전 rootfs, 백업/D2D, 로컬 DoS, 빌드 공급망 위험을 제거하거나 명시적으로 차단한다.
- Codex/Grok OAuth, 동적 모델, 스트리밍, Stop, 대화 복구, Agent 전환, Android 수명주기 복구의 현재 동작을 그대로 유지한다.
- 기존 로그인 세션과 대화 기록을 파괴하지 않는 versioned migration과 rollback 경계를 만든다.
- 공개 배포용 release variant, 외부 제공 signing credential 경계, APK/AAB 자동 검증을 구축한다.
- 선택된 보안 통제를 자동화된 release gate와 Samsung 실기기 검증으로 고정한다.

## 개발 범위

- SEC-001: Android↔Gateway transport를 private Unix domain socket과 peer UID 검증으로 전환
- SEC-002: Codex/Grok credential runtime을 별도 Android UID 경계로 분리
- SEC-003 제한 적용: 현재 Runtime의 package-level SBOM·artifact 무결성·rollback만 적용하고 patched rootfs/Python/secdb 교체는 배포 필수 범위에서 제외
- SEC-004: 민감 데이터의 backup/D2D 제외와 기존 데이터 무손실 migration
- SEC-005: Gateway 연결 timeout, 동시성 상한, slow-client 방어
- SEC-006: Kotlin build cache 권고 완화와 수정 버전 적용
- SEC-007: Gradle dependency verification, locking, wrapper checksum 적용
- SEC-008: nonce cache 포화 내구성 및 telemetry 보완
- 기존 reference/source-map gate 복구와 보안 회귀 통합 gate 추가
- Samsung `secureDebug` 데이터 보존 설치와 기존 로그인 상태 기반 E2E 검증

## 공통 진행 규칙

- 각 Phase는 앞선 Phase의 자체 테스트와 완료 조건을 모두 통과한 뒤에만 시작한다.
- 한 Phase에서는 기능 변경과 보안 경계 변경을 동시에 넓히지 않는다. 먼저 characterization test를 추가한 뒤 최소 구현을 적용한다.
- 현재 public ViewModel/backend/Agent 계약과 Gateway route/body/SSE event 계약은 보존한다. 변경이 불가피하면 adapter 안에서만 흡수한다.
- 보안 전환 중 legacy와 신규 경로를 함께 둘 수 있지만, `secureDebug` 최종 산출물에는 insecure fallback을 남기지 않는다.
- migration은 `preflight → copy/import → destination 검증 → 전환 marker commit → 구 데이터 제거 승인` 순서로 수행한다.
- migration 실패 시 기존 데이터와 실행 경로를 유지하고, 부분 복사본만 안전하게 폐기한다. 기존 credential을 먼저 삭제하지 않는다.
- credential, OAuth URL/code, prompt/response, account metadata를 로그·테스트 fixture·문서에 기록하지 않는다.
- 새 로그는 enum, Boolean, bounded count, stable error code만 허용한다.
- 실제 Provider 호출은 자동 gate에서 수행하지 않는다. 실기기 실제 turn은 사용자 승인과 비민감 합성 prompt를 사용한다.
- 외부 통신은 공식 Codex/Grok CLI가 소유하는 OAuth와 사용자가 시작한 Agent 통신으로 한정한다. Google/Samsung backup, Smart Switch, sync, telemetry 등 무관한 외부 서비스는 검증 목적이라도 호출하지 않는다.
- 새 외부 의존성은 표준 Android/Python/Gradle 기능으로 해결할 수 없을 때만 추가한다.
- 구현 중 발견된 결함은 해당 Phase 범위 안에서 수정하고 `이슈 및 수정`에 기록한다.
- 체크박스는 실제 상태와 일치시킨다. 실패한 항목을 완료 처리하지 않는다.
- Git commit/push는 구현 완료와 별개이며 사용자의 별도 요청 전에는 수행하지 않는다.

## 보안 설계 결정

1. **SEC-001 transport:** 기존 HTTP route와 JSON/SSE 의미를 유지한 채 HTTP/1.1 framing만 Unix domain socket 위로 이동한다. HMAC은 defense-in-depth로 유지한다.
2. **TCP fallback:** unit/debug 비교용 legacy transport는 migration 기간에만 허용한다. `secureDebug` 최종 manifest/build에는 `127.0.0.1:8787` fallback이 없어야 한다.
3. **Socket 소유권:** 앱 private `0700` 디렉터리에 socket을 만들고 양쪽에서 kernel peer UID를 확인한다. stale path는 symlink/type/owner 검사 후에만 정리한다.
4. **SEC-002 격리:** `android:process`만 분리하는 방식은 같은 UID이므로 채택하지 않는다. Codex와 Grok runtime broker를 서로 다른 application package/UID로 분리하고 signature-protected Binder 계약으로 UI 앱과 연결하는 방식을 목표로 한다.
5. **Agent 내부 경계:** 각 broker 안에서 Android↔Python Gateway는 private UDS를 사용한다. UI 앱은 OAuth credential 파일을 전달받거나 읽지 않는다.
6. **rootfs policy:** 현재 번들 rootfs의 hash·package SBOM·provenance와 rollback 경계를 고정한다. patched rootfs와 Python 사전 번들은 Phase 6 제외 범위이며 공개 배포를 차단하지 않는다.
7. **SEC-002 전환 실패:** 별도 UID prototype이 R-01~R-12를 만족하지 못하면 legacy 경로로 공개 배포하지 않는다. P0/P1 보완은 유지하되 공개 release 판정은 `NO-GO`로 남긴다.

## Phase 3. Private Unix domain socket 전환

### 목표

- SEC-001의 고정 loopback 포트 선점, 가짜 서버, 평문 TCP 노출을 제거한다.

### 구현 태스크

- [x] 앱 private `0700` IPC 디렉터리와 inode-checked 고정 socket 이름을 생성한다. Predictable name은 private parent·peer UID·HMAC 경계에서 권한을 넓히지 않으며 process-recovery 발견성을 유지한다.
- [x] socket 경로는 정규화 후 승인된 root 하위인지 확인하고 Linux `sockaddr_un` 107-byte 상한을 적용한다.

## 중단 및 Rollback 기준

- OAuth session 손실, history 복호화 실패, prompt 중복 dispatch, cross-Agent fallback, process 중복 중 하나라도 발생하면 즉시 해당 Phase를 중단한다.
- migration source는 destination 검증 전에 삭제하지 않는다.
- 보안 검증 실패 시 insecure fallback으로 자동 전환하지 않는다. 개발 build에서만 명시적 rollback을 수행한다.
- rootfs/toolchain 변경은 이전 검증 artifact와 hash를 보존해 원인 분리 후 재시도한다.
- SEC-002 별도 UID 전환이 검증되지 않으면 same-UID 구조를 공개 release로 승격하지 않는다. Phase 6 rootfs 정책은 이 중단 기준에서 제외한다.
