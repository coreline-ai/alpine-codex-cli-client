# implement_20260816_081114.md

작성 일시: `2026-08-16 08:11:14 KST`

이 문서는 신규 독립 QA Agent가 모듈 검증과 분리된 실제 Android 사용자 흐름을 새로 설계하고,
현재 source로 만든 APK를 공개 배포 전에 반복 검증하기 위한 작업 문서다.

## 개발 목적

- 설치된 앱을 사용자가 실제로 조작하는 경로에서 설치, 첫 실행, Runtime, OAuth, Agent/모델,
  streaming chat, Stop, 복구, 실패 표시, 성능과 접근성을 전체 검증한다.
- 기존 unit/instrumentation gate는 선행 조건으로만 사용하고 app-level QA 통과 증거로 계산하지 않는다.
- 신규 QA Agent가 기존 구현자의 가정을 따르지 않고 독립적으로 누락·혼동·회귀를 발견하게 한다.
- 같은 절차를 current-source APK마다 재실행할 수 있는 개인정보 안전 QA harness를 만든다.

## 개발 범위

- Samsung `SM-S931N`, Android API 36, `arm64-v8a`
- `debug`, `secureDebug`, 최종 signed `release` 후보의 사용자 관점 차이
- Android launcher/UI/browser/system lifecycle을 통한 black-box/gray-box 검증
- 고정 Boolean, enum, duration, process count만 남기는 redacted evidence
- Codex와 Grok의 독립적인 login/account/model/conversation/Stop/복구 흐름
- app start부터 usable composer까지의 cold/warm/recovery 시간과 안정성
- 반복 실행용 `scripts/app_real_use_qa.py`와 QA 결과 문서

## 제외 범위

- 현재 보존 대상 앱의 uninstall, clear-data, credential/auth 파일 읽기·복사·삭제
- raw OAuth URL/code, account, model name, prompt/response, UI hierarchy, screenshot, broad logcat 보존
- 승인 없는 logout, 유료 turn, Runtime shutdown, release signing, store 제출
- Google/Samsung backup, Smart Switch, sync, analytics 등 별도 외부 서비스
- 다른 연결 기기의 설치·실행·설정 변경
- module/unit test 결과를 실사용 QA PASS로 간주하는 판정
- current-source APK가 아닌 기존 설치 APK 결과를 최신 release 증거로 재사용하는 것

## 공통 진행 규칙

- 각 Phase는 앞선 Phase의 자체 테스트 완료 후에만 시작한다.
- 신규 QA Agent는 source 구현 설명보다 화면과 system-observable 결과를 우선한다.
- Candidate ID는 package/version/update time/source commit/APK SHA-256의 조합으로 고정한다.
- 기존 설치 APK와 current-source APK의 결과를 합쳐 하나의 PASS로 만들지 않는다.
- QA output에는 allowlisted Boolean/enum/count/duration과 stable error code만 허용한다.
- UI XML은 memory 또는 임시 device file에서 allowlist Boolean으로 축약한 뒤 즉시 삭제한다.
- account/model/prompt/response/URL/code, raw log, screenshot은 출력·파일·Git evidence에 남기지 않는다.
- `debug`에서 실제 OAuth가 차단되는 것은 PASS이고, `secureDebug`/`release`에서만 실제 계정을 다룬다.
- 실제 OAuth/turn/logout/shutdown은 각각 계획에 적힌 별도 승인 gate를 통과한 경우에만 실행한다.
- 앱은 자동 prompt retry/replay/cross-Agent fallback이 없어야 하며 QA도 이를 유발하지 않는다.
- 다른 연결 기기는 serial allowlist에서 제외하고 command 실행 전후 무변경을 확인한다.
- 발견 이슈는 증상·영향·재현·증거·임시조치만 먼저 기록하고 원인은 수정 검증 뒤 확정한다.
- 기존 dirty working tree는 reset/stash/rebase/checkout하지 않는다.

## 실사용 PASS 정의

아래 조건을 모두 만족해야 current-source candidate를 실사용 PASS로 판정한다.

1. current source에서 빌드한 정확한 APK가 data-preserving 방식으로 설치돼야 한다.
2. 앱 UI를 통해 Runtime 준비, 기존 OAuth 복구 또는 신규 OAuth, live model, turn, Stop이 동작해야 한다.
3. cold start, warm start, background, force-stop, Gateway/process 재생성 후 자동 prompt 없이 복구돼야 한다.
4. Codex↔Grok 전환 시 account/model/conversation이 섞이지 않고 process가 하나만 선택돼야 한다.
5. offline/timeout/process-loss/invalid state가 crash·무한 spinner가 아닌 stable user action으로 끝나야 한다.
6. 민감 값 없이 candidate/evidence를 재현할 수 있어야 한다.
7. full app matrix의 필수 항목은 `PASS`, 조건부 항목은 승인 또는 입력 부족으로 명시된 `BLOCKED`여야 한다.
