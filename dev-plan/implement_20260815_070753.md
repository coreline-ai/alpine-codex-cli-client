# implement_20260815_070753.md

작성 일시: `2026-08-15 07:07:53 KST`

이 문서는 실제 Samsung 실기기에서 Grok OAuth 이후 상태 유지·Agent 전환·Stop 경로를 권장 순서대로 완성하고, 전체 보안 게이트와 근거 문서를 현재 구현에 맞추기 위한 실행 계획이다.

## 개발 목적
- 로그인 완료 상태가 Android 수명주기와 Agent 전환 뒤에도 안정적으로 유지되는지 검증하고 필요한 결함을 수정한다.
- 실제 Grok 생성 1건을 Stop하여 취소 계약과 감사 로그를 검증한다.
- 누적 Grok Phase 9 구현을 전체 테스트·보안 게이트로 다시 확인하고 인수인계 문서를 실제 상태와 일치시킨다.

## 개발 범위
- 지정 Samsung 실기기의 백그라운드→포그라운드 복귀 검증
- Codex 선택 상태 확인 후 실제 유료 추론 없이 Grok 재선택 검증
- 합성·비민감 프롬프트 1건의 Grok Stop/취소 검증
- 수명주기·선택 상태·취소 경로에서 발견된 프로젝트 결함의 최소 수정
- Python, Android host/unit/lint/build, Grok profile/contract, 보안 evidence 검증
- Grok runbook, E2E 근거, Phase 9 handoff 문서 동기화

## 제외 범위

- 지정 Samsung 외 연결 기기 조작
- release artifact 생성·배포

## 공통 진행 규칙
- 각 Phase는 앞선 Phase의 자체 테스트 완료 후에만 시작한다.
- 구현 중 발생한 이슈는 해당 Phase에서 최소 범위로 수정하고 기록한다.
- 체크박스 상태를 실제 진행 상태와 맞게 업데이트한다.
- 문서에 없는 범위 확장은 하지 않는다.
- 현재 누적 미커밋 변경을 보존하며 reset, stash, checkout으로 사용자 변경을 되돌리지 않는다.
- ADB 대상은 지정 Samsung serial로 고정하고 다른 연결 기기는 조회만 하며 조작하지 않는다.
- 실제 프롬프트 입력 뒤에는 UI hierarchy나 광범위 logcat을 수집하지 않고 `AgentTurnAudit`의 비민감 감사 필드만 확인한다.
- Stop 턴은 합성 프롬프트를 정확히 1회 전송하고 자동 재시도하지 않는다.
- 상태 확인은 사용자/응답 원문 대신 고정 UI label, Boolean, process count, redacted audit 값으로 제한한다.
- APK는 `secureDebug` 변형만 실기기에 적용하고 release 서명/배포 범위로 확장하지 않는다.

## 결정 기록
- 권장 진행 순서는 수명주기 유지 → Agent 전환 → Stop → 전체 게이트 → 문서 동기화로 고정한다.
- Codex 전환 검증은 선택·준비 상태까지만 수행하고 메시지는 보내지 않는다.
- Grok Stop은 전송 전에 동일 위치의 전송/Stop action 좌표를 확보하고, 메시지 입력 이후 UI dump 없이 한 번만 실행한다.
- 로그아웃과 Runtime 정리는 credential/runtime 파괴 가능성이 있어 이번 구현 승인에 포함하지 않는다.
- Git commit/push는 구현 완료와 별개이며 사용자의 별도 요청 전에는 수행하지 않는다.

## 잔여 리스크 / 후속 과제
- 공식 Grok CLI가 cancel 승인 뒤 이전 prompt RPC를 늦게 종료할 수 있다. 앱/Gateway는 즉시 terminal과 late-result guard로 격리하지만 upstream 변경 시 regression을 유지해야 한다.
- reference live working tree는 외부 변경 가능성이 있으므로 gate는 문서화된 기준 commit snapshot에서 재현해야 한다.
- official Grok logout과 Runtime/child-process cleanup은 credential/runtime 파괴 가능성이 있어 별도 사용자 승인 전에는 수행하지 않는다.
- 현재 누적 working tree는 uncommitted다. Git commit/push는 별도 요청에서 전체 diff를 검토한 뒤 수행한다.
