## 현재 확정 기준선

1. 작업 branch는 `codex/implement-grok-agent`, 시작 HEAD는 `7b431f2`다.
2. Phase 0~8은 완료됐다. Phase 9에서 Samsung package 확인, secure APK update-install,
   Alpine/Python/Gateway 시작, Grok ACP 진단 및 backend 복구까지 완료됐다.
3. 공식 ACP 0.10.4 extension wire는 logical `x.ai/*`가 아니라 exact `_x.ai/*` JSON-RPC
   method를 사용하도록 제품 allowlist, adapter, fake ACP, fixture와 verifier가 수정됐다.
4. 제품 Gateway의 다중 스레드 안에서 `subprocess.Popen(preexec_fn=...)`을 사용해 Grok child가
   exec 전에 종료되던 결함은 전용 `umask=0o077` 인자로 교체됐다. shipping Grok ACP source에
   `preexec_fn`이 다시 들어오면 verifier가 실패한다.
5. 위 수정 뒤 focused Python 45 tests와 전체 secure-debug milestone이 PASS했다. 최종 결과는
   Python 97 tests, Gradle 516 tasks와 JVM/Android unit, lint, APK, artifact, ACP, sensitive
   evidence, source-map 및 Runtime manifest gate PASS다.
6. Samsung에 설치된 최신 secure-debug APK는 다음과 같다.

   - application ID: `dev.alpine.codexclient.debug`
   - versionCode: `2`
   - versionName: `0.2.0-secure-debug`
   - non-debuggable, debug certificate
   - size: `161107766` bytes
   - SHA-256: `cd35461b5621da02b35db8f120f16487072436c611e11aad0a6ab29e0cda5f1b`
   - certificate SHA-256: `6bfd1a305ea7958397ca2d4c0a4917ea90b6b6fe75ea8b38b56001c05b4a1092`

7. 실제 Samsung에서 Runtime/Gateway는 RUNNING이고 product process invariant는
   `app=1, PRoot=1, Python=1, Codex child=0, Grok child=1`이다.
8. 수정된 제품 supervisor 기반 `Grok ACP 점검`은 content-free `READY`를 반환했다. 실제
   Gateway에서도 Grok child가 즉시 종료되지 않고 1개로 유지됨을 확인했다.
9. 사용자는 `2026-08-13 KST`에 **Grok OAuth 시작**을 승인했다. Grok 로그인 action은 아직
   실행하지 않았고 OAuth/model/prompt/Stop/logout dispatch는 모두 0이다.
10. 외부 브라우저 계정 승인은 아직 완료되지 않았다. 브라우저가 열리면 사용자가 직접 공식
    xAI 승인을 완료해야 한다.
11. **Grok logout은 승인되지 않았다.** 로그아웃 직전에 별도 명시적 승인을 받아야 한다.
12. 현재 source/test/docs 변경과 untracked test/Goal 문서는 Phase 9 진행분이다. reset,
    checkout 복원, stash, rebase, pull 또는 다른 방식으로 덮어쓰지 않는다.

## 고정 작업·보안 규칙

1. 모든 Android mutation 직전에 연결 기기 목록에서 목표 Samsung `SM-S931N`,
   `arm64-v8a`, API 36과 target application ID를 다시 확인한다. serial은 터미널에서만 일시
   확인하고 문서·로그에는 `SAMSUNG_TARGET` alias만 남긴다.
2. 다른 연결 기기에는 어떤 mutation도 수행하지 않는다.
3. 관련 없는 `com.stt.benchmark`와 `com.stt.benchmark.deviceTest`가 focus를 가져가더라도
   force-stop, disable, uninstall, clear-data 또는 입력을 수행하지 않는다.
4. 화면 좌표 입력 직전에 `dumpsys window`로 target app 또는 target-owned popup의 focus를
   확인한다. focus가 다르면 tap/text/keyevent를 보내지 않는다.
5. OAuth 시작 뒤에는 screenshot과 UI dump를 사용하지 않는다. URL/challenge/code, browser
   state, token, account field, model catalog 원문, prompt/response 원문을 terminal, logcat,
   문서, 캡처 또는 Git에 남기지 않는다.
6. 인증과 채팅은 공식 Grok CLI의 ACP stdio 및 `grok.com` Device OAuth만 사용한다. API key,
   앱 OAuth client ID, CLI fingerprint, 직접 xAI HTTPS, Provider fallback을 추가하지 않는다.
7. 자동 retry, 자동 prompt replay, 자동 재전송, Agent fallback을 구현하거나 실행하지 않는다.
8. 실패한 OAuth·prompt·Stop·logout action은 같은 요청에서 자동으로 다시 누르지 않는다.
9. uninstall, clear-data, downgrade, credential/config 직접 읽기·복사·수정·삭제를 금지한다.
10. build와 설치는 secure/debug 경로만 사용한다. release/store signing, release APK/AAB는
    사용하지 않는다.
11. `AgentTurnAudit` 이외의 raw chat 로그를 증거로 만들지 않는다. audit은 먼저
    `scripts/verify-agent-turn-audit.py`의 해당 mode를 통과시킨다.
12. 계획 체크박스는 실제 증거가 통과한 직후 갱신한다. 실패도 민감 원문 없이 stable
    stage, 원인, 수정, 재검증 결과를 해당 Phase에 기록한다.
13. 관련 없는 기존 사용자 변경을 되돌리거나 덮어쓰지 않는다.
14. 바이너리, APK, credential, 캡처, 생성 asset을 Git에 추가하지 않는다.
15. Phase 9 완료 단위로 로컬 commit하되 원격 push는 하지 않는다.
16. 실제 전체 완료 정의를 충족하기 전에는 Goal을 완료로 표시하지 않는다.

- [ ] 실제 모델 이름은 기록하지 않고 catalog count와 selected-ID 일치 Boolean만 남긴다.
- [ ] 첫 authenticated fixed-profile session에서 tool, subagent, MCP, filesystem, terminal
      profile event가 모두 0인지 확인한다. 하나라도 0이 아니면 prompt 전에 중단한다.
- [ ] 짧고 비민감한 테스트 메시지를 정확히 1회만 전송한다.
- [ ] prompt/response 원문을 저장·출력하지 않는다.

### 자체 테스트·완료 조건

- [ ] user node 1, assistant node 1, terminal event 1이다.
- [ ] streaming/error 상태가 terminal 뒤 안정적으로 종료된다.
- [ ] Android dispatch 1, Gateway dispatch 1, prompt replay 0, Agent fallback 0이다.
- [ ] retry는 승인된 G1 범위와 일치하며 예상 밖 retry는 0이다.
